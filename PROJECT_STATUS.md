### P4.04 — Callback routing fix (PR #62, merged to dev)
`_needs_search` in `turn_runner.py` derived `_booking_flow` from `_req_day` (detects
"utterance names a day") without distinguishing a new-visit slot request from a callback
request. "Call me back tomorrow" hit the same gate as "I want to visit tomorrow", so Rule 1
at ~line 2912 unconditionally overwrote the model's already-correct `schedule_callback`
proposal with `locate_centre`. Fix: `_needs_search` now short-circuits when the model has
already proposed `schedule_callback` (that tool has no centre/slot dependency).
Verified 2/2 on an isolated OpenAI instance after 0/5 across five previous prompt-only
attempts. Conversation regression suite run before and after — the fix resolves this
scenario plus two related failures; four pre-existing flaky failures appeared in the
post-fix run, each with a documented root cause unrelated to this change.
Also hardened: `locate_centre` tool description clarified to state it is not a callback
prerequisite (defence in depth, did not resolve the root cause alone).
